# TK_SABR

منصة تحليل حسابات TikTok — المبرمج المجهول.
React + TypeScript + Vite + Tailwind؛ خادم Node/Express؛ PostgreSQL وGoogle/email Auth عبر Supabase. أُعيد استخدام المشروع الموجود مع استبدال سحب صفحات TikTok والمسارات غير الموثوقة بمسار مصدر مخوّل. لا توجد بيانات وهمية في التشغيل.

## التشغيل

Node 24:

```sh
npm ci
cp .env.example .env
npm test
npm run lint
npm run build
npm run dev
# production:
NODE_ENV=production npm start
```

الموقع المحلي على منفذ 3000. إعدادات `VITE_` عامة وتدخل حزمة المتصفح وقت البناء، والبقية أسرار خادمية فقط. لا تضع أي سر في Repository variables أو كود المتصفح. للتشغيل الكامل اضبط المزود وSupabase أولاً. غياب المزود يُرجع 503 واضحاً، ولا يختلق نتائج.

## مصدر TikTok

Display API الرسمي يتطلب موافقة صاحب الحساب وصلاحيات مناسبة، ولا يسمح تلقائياً بفحص أي يوزر. يدعم هذا الإصدار توكن موافقة موجوداً في الخادم لحساب واحد؛ ربط TikTok OAuth متعدد المستخدمين وتجديد التوكن تلقائياً غير منفذين. فحص حسابات أخرى يحتاج عقد مزود مخوّل يدعم واجهة [API](docs/API.md). لا يوجد مزود مدفوع أو مرخص مرفق بالمشروع. Research API ليس بديلاً لمنصة تجارية.

الذكاء الاصطناعي اختياري عبر مزود OpenAI-compatible. بدونه يُنشأ تقرير معلن بالقواعد البرمجية، فقط بعد نجاح جلب البيانات. تقارير AI قد تخطئ، ولا تعد مصدراً للإحصائيات.

## قاعدة البيانات والحسابات

أنشئ مشروع Supabase خاصاً بـTK_SABR، ثم راجع وطبّق `backend/schema.sql` مرة واحدة. السكربت يعرّف RLS لعزل التقارير، وجداول الصلاحيات والصيانة. لا يُطبَّق على مشاريع أخرى. في Auth فعّل البريد وGoogle الرسمي، واضبط Client ID/secret في Supabase فقط، وOAuth callback في Google كما يعرضه Supabase. أضف عنوان الواجهة النهائي إلى Site URL وRedirect allowlist. ضع publishable key في الواجهة وservice-role في Backend فقط.

أضف UUID المستخدم الموثق إلى tksabr_admins من اتصال إداري. بيانات user_metadata ليست مرجعاً للصلاحيات. مسارات الحفظ والإدارة تتحقق من الجلسة لدى خادم Supabase ثم من الملكية/الصلاحية. لا يوجد حفظ تلقائي للفحص العام. انتهاء حفظ التقارير 30 يوماً؛ فعّل مهمة pg_cron اليومية الموثقة في schema للحذف الفعلي. لا يكفي إخفاء التقارير المنتهية.

## GitHub Pages + Backend

1. ارفع المشروع إلى `almajhool-dev/tk-sabr`.
2. انشر Backend باستخدام `render.yaml` إلى بيئة Node تدعم Node 24 أو بيئة Node مماثلة. لم تُنشأ خدمة مدفوعة تلقائياً. Cloudflare Workers ليس هدف هذا الخادم Express الحالي.
3. اضبط `ALLOWED_ORIGINS=https://almajhool-dev.github.io` على الخادم، وVITE_API_BASE_URL=عنوان Backend النهائي في Repository variables. عنوان API بلا slash نهائي. لا تضمّن مسار المستودع في Origin.
4. أضف متغيري VITE_SUPABASE_URL وVITE_SUPABASE_PUBLISHABLE_KEY العامين إلى Repository variables.
5. فعّل Settings → Pages → Source: GitHub Actions، ثم أضف Repository variable باسم PAGES_ENABLED وقيمته true. المستودع الخاص قد يحتاج خطة GitHub تدعم Pages الخاص؛ لا تحوّل المستودع عاماً قبل مراجعة محتواه وموافقة صاحبه.
6. `pages.yml` يبني ويختبر وينشر الواجهة فقط؛ `build.yml` يشغّل الفحص والبناء أيضاً. لا ينفذ GitHub Pages كود Backend.
7. تحقق من الواجهة، ثم GET /api/health، وفحص حساب مصرح فعلياً، وتسجيل الدخول والخروج، وعزل مستخدمين، ورفض مدير غير مخول قبل اعتبار الموقع جاهزاً.

حدود الخطط المجانية قابلة للتغيير: GitHub Pages للاستضافة الثابتة، وقاعدة البيانات/المصادقة والـBackend لكل منها حصص وقد تتوقف الخدمة المجانية أو تدخل السكون. لا يوجد ضمان أن مصدر TikTok المخوّل مجاني. هذا المشروع لا يعد بتوفر مطلق أو فحص أي حساب.

## الاختبارات والتسليم

`npm test`: اختبارات المدخلات والتحليل ومحول المزود ومسارات HTTP والأمان باستخدام بيانات اختبار منفصلة لا تدخل الإنتاج.
`npm run test:live`: اختبار تكامل حقيقي اختياري باستخدام LIVE_TEST_USERNAME وأسرار مصدر مخوّل. عند غيابها يُسجل skipped وليس نجاح تكامل.
راجع [حالة التنفيذ](docs/STATUS.md) للفحوص الفعلية والحدود.

الواجهة تدعم العربية وEnglish، تقليل الحركة، إظهار القيم الناقصة، ورسماً للمقارنة بين فيديوهات العينة فقط. تصدير PDF يستخدم طباعة المتصفح وحفظ كـPDF؛ ليس تنزيل ملف PDF خادمي تلقائياً. لا توجد رسوم نمو تاريخية مختلقة. بعض النصوص الآتية من الخادم بالعربية حالياً.

## ملاحظات التشغيل والأمان

محدد الطلبات والكاش وعدّادات الأخطاء محلية ومحدودة الذاكرة، وتُصفّر عند إعادة التشغيل. قبل زيادة عدد نسخ الخادم استخدم محدد طلبات/كاش مشتركاً. عند النشر خلف وكيل معروف، اضبط TRUST_PROXY_HOPS وفق عدد الوكلاء الموثوق؛ لا تستخدم trust proxy=true عشوائياً. بدونه قد يشترك الزوار خلف الوكيل في حصة واحدة. الإدارة تعدل الحد من 1 إلى 120 طلباً/دقيقة/عنوان اتصال، وتعرض آخر 50 خطأ برموزه فقط دون أسرار.

فحص المتصفح: ثبّت Playwright وChromium في بيئة اختبارات منفصلة، شغّل الخادم المحلي، ثم node tests/browser-check.mjs. يمكن تحديد PLAYWRIGHT_MODULE لمسار مكتبة جاهزة وTEST_BASE_URL لعنوان الخادم. الاختبار يستخدم بيانات اختبار معترضة لا تدخل الإنتاج. لم ينجح تشغيل المتصفح في بيئة التسليم الحالية؛ راجع STATUS.
